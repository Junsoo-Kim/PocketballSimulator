# Pocketball Simulator

SSAFY 내 알고리즘 대회인 **일타싸피**(포켓볼을 코드로 치는 대회)를 대비하기 위해 만든 시뮬레이터입니다.
`player.Player`의 `getAngle()`, `getPower()`만 채워 넣으면, GUI로 실제 대회와 비슷한 환경에서 내 알고리즘을 테스트해볼 수 있습니다.

<img src = "./sample.gif">

실제 대회에서는 코드를 `main()`에 전부 작성하고 `power`와 `angle` 변수를 서버에 메시지로 보내는 방식으로 진행됩니다. 이 시뮬레이터는 그 환경을 흉내낸 **보조 연습 도구**이며, 공식 대회 클라이언트가 아닙니다.

---

## 1. 이번에 개선한 점

원래 이 프로젝트는 "얼추 포켓볼처럼 동작하는 시뮬레이터" 수준이었고, README에도 "실제 대회 클라이언트와는 각도 체계, 물리 상수, 홀 모양 등이 달라서 넣기가 더 어렵다"는 점만 밝혀둔 채 그 차이를 좁히려는 시도는 없었습니다. 이번에 실제 대회 후기/커뮤니티에 공개된 참가자 코드들을 조사해서, 아래와 같이 **실제 클라이언트에 최대한 가깝게** 만들고, 시뮬레이터 자체의 버그와 미완성 부분도 손봤습니다.

| 항목 | 이전 | 개선 후 | 근거 |
|---|---|---|---|
| 각도 체계 | 수학적 표준 각도(0도=+x, 반시계 증가)를 그대로 사용 → 실제 대회에 낼 때 "270도쯤 돌려야 한다"는 변환이 별도로 필요했음 | `getAngle()`이 **실제 대회 클라이언트와 동일한 체계**(0도=+y 방향, 시계 방향 증가)로 값을 주고받도록 변경. `Game`이 내부적으로만 표준 각도로 변환해서 물리 연산에 사용 | 실제 서버를 상대로 동작했던 참가자 코드의 각도 변환식(`degree = ((90 - degree) + 360) % 360`)을 역으로 확인 |
| 마찰 물리 | 매 프레임 속도에 일정 비율(1%)을 곱해 감속(지수적 감속) | 매 프레임 **일정한 크기만큼** 감속하다 멈추는 등감속 모델로 교체 (`Constant.FRICTION_DECEL`) | 참가자 코드가 `v² = base + 2·μ·거리` 형태의 등가속도 공식으로 필요 파워를 역산하고 있어, 실제 물리도 이 방식에 가깝다고 판단 |
| 홀(포켓) 위치 | 테이블 모서리/변의 정확한 좌표(`(0,0)`, `(127,0)` 등) | 공 반지름의 일정 비율만큼 안쪽으로 당겨진 위치 (`Constant.HOLE_INSET_RATIO`) | 참가자 코드들이 공통적으로 홀 좌표를 안쪽으로 보정해서 계산 |
| 포켓된 공의 좌표 | `(0, 0)` — 테이블 모서리(홀 근처)의 실제 좌표와 겹쳐서 혼동 소지 있음 | 테이블 밖을 뜻하는 **`(-1, -1)`** | 실제 서버가 포켓된 공을 `[-1.0, -1.0]`으로 내려주는 것을 확인 |
| 턴/무승부 규칙 | 3파울 패배 또는 완주 외에는 종료 조건이 없어 무한 진행 가능 | 모든 플레이어가 `Constant.MAX_TURN`(기본 20)턴을 쓰면 종료, **파울이 적은 쪽 승리(동률이면 후공 승리)** | 실제 대회 반 대항전 규칙 |
| `Player` 예시 로직 | 그냥 첫 목적구를 향해 직선으로 조준 (방해구·홀 선택 고려 없음) | **이미지볼(고스트볼)** 조준점 계산 + 방해구 검사 + 여러 (목적구, 홀) 조합 중 가장 만만한 샷 선택 | 대회 참가자 후기에서 공통적으로 언급된 전략 |
| `Ball.setVeloc` | 인자를 무시하고 항상 속도를 0으로 설정하는 버그 | 전달받은 값을 실제로 대입하도록 수정 | 코드 리뷰로 발견 |

> ⚠️ 위 수치들(마찰 계수, 홀 인셋 비율 등)은 **공식 문서가 아니라 커뮤니티가 역분석/추정한 값**입니다. 정확한 대회 클라이언트와 100% 동일하다고 보장할 수는 없으니, 이 시뮬레이터는 여전히 감각을 익히기 위한 보조 도구로만 활용하고, 최종 코드는 반드시 실제 대회 환경에서도 검증하세요.

## 2. 사용 설명서

### 2.1 준비물
- JDK 8 이상 (OpenJDK 17+ 환경에서 확인함)
- IntelliJ IDEA 등 자바 IDE (이 저장소에 `.idea` 설정이 포함되어 있어 바로 열기 편합니다) — 또는 터미널 + `javac`/`java`

### 2.2 내 알고리즘 작성하기
1. [`src/player/Player.java`](src/player/Player.java) 파일을 엽니다. `//do not modify above` 아래 부분(`getAngle()`, `getPower()`와 그 보조 메서드들)을 자유롭게 수정합니다.
2. `Player`가 참고할 수 있는 정보:
   - `this.order` — 내 플레이어 번호(0 또는 1). 2인전에서 0번은 홀수 번호 공, 1번은 짝수 번호 공이 목적구입니다.
   - `this.balls` — 현재 공들의 좌표. `balls[0]`이 흰 공(수구), `balls[balls.length-1]`이 마지막 공(검은 공)입니다. `balls[i][0]`이 x, `balls[i][1]`이 y좌표이며, **포켓된 공은 `(-1, -1)`** 로 표시됩니다.
   - `controller.Game.HOLES` — 6개 홀의 좌표 (`double[][]`).
   - `model.Ball.DIAMETER`, `model.Constant.*` — 공 지름, 테이블 크기, 최대 파워 등 각종 상수.
3. `getAngle()`은 **0도 = +y 방향, 시계 방향으로 증가**하는 값을 반환해야 합니다(실제 대회 클라이언트와 동일한 체계). 기본 제공되는 `Player.java`의 `toGameAngle()` 메서드가 표준 수학 각도를 이 체계로 바꿔주니, 대부분의 경우 그 함수를 그대로 이용하면 됩니다.
4. `getPower()`는 0~100 사이의 값을 반환하면 됩니다(범위를 벗어나면 자동으로 clamp됩니다).

기본으로 들어있는 예시 로직은 "이미지볼(고스트볼) 위치를 계산해 방해구 없이 넣을 수 있는 조합 중 가장 쉬운 샷을 고르고, 마땅한 게 없으면 가장 가까운 목적구를 직선으로 노려본다"는 수준입니다. 뱅크샷(쿠션을 이용한 샷), 더 정교한 샷 난이도 평가(각도가 작을수록 쉬운 샷이라는 점 등) 같은 부분은 직접 발전시켜봅시다.

### 2.3 실행하기

**IntelliJ IDEA에서:**
프로젝트를 열고 `src/Main.java`의 `main()`을 실행합니다.

**터미널에서:**
```bash
# 프로젝트 루트에서
javac -d out $(find src -name "*.java")   # Windows PowerShell이면: javac -d out (Get-ChildItem -Recurse src -Filter *.java).FullName
java -cp out Main
```

실행하면 아래 메시지가 콘솔에 나타납니다.
```
플레이어 수(최대 2), 플레이어 별 공 수(최대 2)를 빈 칸 하나를 두고 입력해주세요.
```
예를 들어 `2 2`를 입력하면 흰 공 1개 + 목적구 4개 + 검은 공 1개, 총 6개 공으로 실제 대회(반 대항전)와 동일한 구성으로 게임이 시작되며, GUI 창이 뜹니다.

- 두 플레이어 모두 `Player.java`의 로직을 그대로 사용합니다(`order`만 다름). 서로 다른 전략을 비교해보고 싶다면, `order` 값에 따라 분기하도록 `Player.java`를 수정하세요.
- 게임 진행 상황(누구 차례인지, 몇 번 공을 넣었는지, 파울/승패 등)은 콘솔에 출력됩니다.
- 공이 멈출 때까지 자동으로 진행되며, 모든 공이 멈추면 다음 플레이어(또는 목적구를 넣었다면 같은 플레이어)의 턴으로 넘어갑니다.

### 2.4 동작을 바꿔보고 싶다면
[`src/model/Constant.java`](src/model/Constant.java)의 값들을 조정하면 게임 난이도나 물리 느낌을 바꿀 수 있습니다.

| 상수 | 의미 |
|---|---|
| `TABLE_COR` | 쿠션(벽) 반발 계수 |
| `FRICTION_DECEL` | 프레임당 감속량(등감속 마찰) |
| `HOLE_INSET_RATIO` | 홀을 모서리에서 안쪽으로 당기는 정도(공 반지름 대비 비율) |
| `MAX_FOUL` | 이 횟수만큼 파울하면 패배 |
| `MAX_TURN` | 이 턴 수를 다 쓰면 파울 적은 쪽 승리로 게임 종료 |

## 3. 게임 규칙
실제 대회(반 대항전)의 규칙을 최대한 그대로 따릅니다.

- 흰 공 1개 + 목적구(플레이어 별 공 수 × 플레이어 수)개 + 검은 공 1개로 진행됩니다. 2:2(공 2개씩)면 실제 대회와 동일하게 흰공 1 + 목적구 4 + 검은공 1, 총 6개입니다.
- 플레이어가 2명일 때, 0번 플레이어는 홀수 번호 공을, 1번 플레이어는 짝수 번호 공을 목적구로 삼습니다.
- 목적구를 포켓에 넣으면 같은 플레이어가 계속 턴을 이어갑니다.
- 자신의 목적구를 모두 넣기 전에 검은 공(마지막 번호 공)을 넣으면 즉시 패배합니다.
- 다음 세 경우는 파울입니다: 아무 공도 못 맞힘 / 목적구가 아닌 공을 먼저 맞힘 / 목적구가 아닌 공을 포켓. 파울이 `Constant.MAX_FOUL`(기본 3)회 누적되면 패배합니다.
- 흰 공을 포켓하면 테이블 중앙에 다시 놓고 게임을 이어갑니다.
- 모든 플레이어가 `Constant.MAX_TURN`(기본 20)턴을 다 쓰면 게임이 종료되고, 파울이 더 적은 플레이어가 승리합니다. 파울 수가 같다면 후공(나중 순서) 플레이어가 승리합니다.

## 4. 패키지 구조
사실 구성 요소들 사이의 의존 문제가 여전히 남아있지만, 전체적으로는 MVC 패턴을 따르는 방식으로 만들었습니다.

### `model`
당구공에 해당하는 `Ball` 클래스가 있습니다. 내부에는 공의 현 위치, 다음 위치, 속력, 유효 여부, 색 등의 필드와, 부딪히고 튕기는 등의 물리를 구현한 메서드들이 있습니다.
`Vector` 클래스는 공의 움직임 및 충돌 계산을 위해 필요한 2차원 벡터 클래스로, 단위 벡터, 내적, 크기를 구하는 메서드 등이 있습니다.
게임 내 여러 상수값들을 넣어 놓은 `Constant` 클래스도 있습니다.

### `controller`
게임의 상태 및 로직을 처리하는 `Game` 클래스가 있습니다.

### `view`
자바 Swing으로 게임 화면을 그리는 `Display` 클래스가 있습니다.

### `player`
대회 참가자가 직접 채워 넣는 `Player` 클래스가 있습니다. (사용법은 [2.2](#22-내-알고리즘-작성하기) 참고)
